# World Manager — 사용 설명서

로컬 PC에서 판타지 세계관을 칸 나눠 정리하는 프로그램입니다.  
웹사이트 배포·계정·요금제는 없습니다. 데이터는 전부 이 컴퓨터에 남습니다.

이 문서는 **앱 사용법**과, Cursor에서 쓰는 **MCP·에이전트 스킬·소설 파이프라인**까지 한곳에 모은 안내입니다.

## 1. 한눈에 보기

| 하고 싶은 일 | 이렇게 |
|---|---|
| 앱 켜기 | `world-manager/열어보기.bat` |
| 앱 끄기 | `world-manager/종료하기.bat` |
| 주소 | http://127.0.0.1:8777/world-manager/ （모든 PC에서 같음, 이 컴퓨터 전용） |
| 데이터 | `data/worlds/<세계관이름>/` |
| 동작 점검 | `python scripts/smoke-world-manager.py` |
| CSS 합치기 | `python scripts/bundle-world-manager-css.py` |
| 코드 저장소 | https://github.com/paakseongjin/worldmanager |

소설·TRPG 설정을 메모장에 흩어 두면 “확정인지, 어제 고친 파일이 어디인지” 금방 헷갈립니다.  
World Manager는 **처음부터 칸(모듈)을 나눠 두고**, 그 안에만 설정을 쌓게 해 둡니다.

## 2. 설치와 실행

### 필요한 것

- Windows
- Python 3
- 브라우저 (넓은 PC 화면 권장)

### 켜기 / 끄기

1. `world-manager/열어보기.bat`을 실행합니다.
2. 브라우저가 열리고 로컬 서버(포트 **8777**)가 붙습니다.
3. 이미 서버가 켜져 있으면 브라우저만 다시 열립니다.
4. 끌 때는 `world-manager/종료하기.bat`을 사용합니다.

화면이 예전 그대로면 **Ctrl+Shift+R**로 강력 새로고침하세요. CSS·JS 캐시가 남을 때가 있습니다.

## 3. 화면으로 세계관 만들기

### 3-1. 첫 화면 — 세계관 고르기

1. 제목 칸에 이름을 넣고 **만들기** → 폴더가 생기고, 큰 분류(모듈) 16개가 자동으로 깔립니다.
2. 카드 또는 **열기**로 들어갑니다. 카드가 많으면 ‹ › 또는 옆으로 밀어 넘깁니다.
3. **삭제**로 휴지통에 보냅니다. 당장 파일이 날아가지는 않습니다.  
   - 휴지통에서 되돌릴 수 있습니다.  
   - **완전 삭제**는 확인 창에 `DELETE`를 직접 입력해야 합니다.
4. 목록 옆 안내(느낌표) 아이콘 → 그 화면 쓰임새 안내.  
   밝은/어두운 화면도 여기서 바꿉니다.

### 3-2. 기본으로 깔리는 칸 (모듈 16개)

새 세계관마다 왼쪽 **모듈** 목록에 아래가 순서대로 들어갑니다. 번호는 정렬용입니다.

| 번호 | 이름 | 무엇을 적나 |
|------|------|-------------|
| 00 | 절대 기준 | 흔들면 안 되는 규칙과 금기 |
| 01 | 우주론 | 차원, 사후세계, 세계를 움직이는 힘 |
| 02 | 신화 | 신·창세·예언. 누가 믿고 누가 부정하는지 |
| 03 | 마법 | 힘보다 규칙·대가·한계를 먼저 |
| 04 | 세계 | 지리·기후가 문화·무역을 만드는 방식 |
| 05 | 종족 | 종족과 생물. 인간 복사판이 아닌 이유 |
| 06 | 세력 | 왕국·교단·길드. 권력과 갈등의 뿌리 |
| 07 | 인물 | 겉모습, 속마음, 이야기 순 |
| 08 | 물건 | 누가 만들었고, 대가는 무엇인지 |
| 09 | 언어 | 이름과 말의 규칙 |
| 10 | 역사 | 과거가 오늘을 흔드는 사건 |
| 11 | 신앙 | 일상 의식·금기, 권력이 신앙에 받는 영향 |
| 12 | 용어 | 작위·속어. 한 줄 정의 |
| 13 | 연표 | 언제, 무엇이, 왜. 시간 순 |
| 14 | 이야기 | 소설·시나리오 사건 (설정과 칸을 나눔) |
| 15 | 관계 | 설정끼리 왜 이어지는지 |

다 채울 필요는 없습니다. 오늘 손댈 칸만 열고, **모듈 추가**로 큰 분류를 더 넣을 수 있습니다. 왼쪽 목록은 ‹ 로 접을 수 있습니다.

### 3-3. 보드에서 설정 쌓기

1. 왼쪽에서 칸을 고르면 가운데에 보드가 열립니다.
2. **그룹 추가**로 묶음을 만들고, 그 안에 설정 카드를 넣습니다.
3. 카드를 누르면 속성 문단·관계를 고칩니다.
4. **확정 / 임시 / 추측** 같은 캐논 상태로 “절대 안 흔든다 / 아직 고민 중”을 구분합니다.
5. 상단 검색으로 모듈·설정 이름을 찾을 수 있습니다.
6. 지구 아이콘 → 세계관 목록으로 돌아갑니다. 나갈 때 한 번 더 저장합니다.

### 3-4. 지도

상단 지도 아이콘을 누르면, 저장할 때마다 맞춰 둔 레벨·그룹·관계 연결을 코드맵처럼 봅니다.  
이름이 비어 있으면 “올릴 게 없다”는 안내만 나옵니다. 데모 데이터(`wm_demo_` 등)는 넣지 않습니다.

## 4. 데이터가 저장되는 곳

한 세계관 = 폴더 하나입니다.

```text
data/worlds/<세계관이름>/
  world-bible.json   ← 본문 (기준 원본)
  markdown/          ← 모듈·설정별 .md (앱이 JSON에 맞춰 자동 생성)
  backups/           ← 서버가 약 10분마다 덮어쓰는 백업
```

휴지통으로 보낸 세계관은 `data/worlds/_trash/`로 옮겨집니다.

**중요**

- 앱에서 고치면 JSON이 바뀌고, 같은 내용이 `markdown/`에도 맞춰집니다.
- 화면에서 마크다운을 직접 치는 편집기가 **아닙니다**.
- 다른 프로그램으로 md만 고치면, 다음에 앱에서 저장할 때 JSON 기준으로 다시 맞춰질 수 있습니다.

기타 메뉴의 **백업 저장**은 경로를 고르면 JSON을 둡니다(일부 브라우저는 다운로드로 대체). **백업 불러오기**는 그 파일을 다시 읽는 용도입니다.

## 5. 폴더 구조와 개발 메모

```text
worldmanager/
  world-manager/     화면(HTML·CSS·JS), 열어보기/종료 bat
  data/worlds/       세계관 데이터
  scripts/           로컬 서버, 스모크 점검, CSS 합본
  docs/design/       디자인 참고
  .cursor/mcp.json   이 프로젝트용 MCP 설정
  .cursor/skills/    소설·세계관 파이프라인 스킬
  .agents/skills/    제품 작업용 스킬 (아래 8장)
  AGENTS.md          에이전트가 따를 짧은 규칙
  README.md          지금 보고 있는 글
```

로컬 서버는 `scripts/world-manager-server.py` (포트 8777)입니다.  
세계관 만들기·열기·저장·휴지통·자동 백업·마크다운 맞춤을 여기서 처리합니다.

화면 스크립트 로드 순(제품 코드맵):

```text
seed-data → constants → theme
store → store-maps → store-query
templates/shell
module-rail → board → board-identity → module-page → world-map → world-picker
nodes → backup
main
```

- 전역 이름: `window.WorldManager` (코드 안에서는 `BF`)
- CSS: `world-manager/styles/*.css`를 고친 뒤  
  `python scripts/bundle-world-manager-css.py`로 `styles.css`를 갱신합니다.
- 동작 점검(서버 켠 상태):  
  `python scripts/smoke-world-manager.py`

에이전트에게 맡길 때 기본 규칙은 `AGENTS.md`를 따릅니다.  
커밋·푸시는 **직접 요청했을 때만** 합니다.

## 6. GitHub

### 이 저장소가 하는 일

- **공식 코드 보관소**: https://github.com/paakseongjin/worldmanager  
- 로컬에서 만든 앱·스크립트·에이전트 안내를 GitHub `main`에 맞춰 둡니다.
- World Manager는 **로컬 전용 앱**입니다. GitHub에 올린다고 자동으로 웹사이트가 배포되지는 않습니다.

### 일상적으로 알아 두면 좋은 것

| 상황 | 안내 |
|------|------|
| 코드만 백업하고 싶을 때 | 커밋 후 `main`에 푸시 (요청할 때만 에이전트가 수행) |
| 공식 배포라고 부를 때 | 보통 커밋 메시지에 `공식 배포`를 쓰고 `main`에 반영합니다 |
| 강제 푸시(`--force`) | 히스토리를 덮어씁니다. **명시적으로 요청했을 때만** 합니다 |
| 올리지 않는 것 | `_workspace/` 임시물, 테스트용 `wm_demo_` 데이터, 개인 메모 잔해 |

### 클론해서 쓰는 경우 (다른 PC)

1. 저장소를 클론합니다.
2. Python 3를 준비합니다.
3. `world-manager/열어보기.bat`으로 실행합니다.
4. Cursor를 쓴다면 이 폴더를 연 뒤, 아래 MCP·스킬이 보이는지 확인합니다.

## 7. Cursor MCP (도구 연결)

MCP는 Cursor 에이전트가 **파일·생각 정리·코드 구조**를 다루도록 붙인 도구입니다.  
설정 파일: `.cursor/mcp.json`  
실행 래퍼: `.cursor/scripts/run-mcp.mjs`

이 프로젝트에 기본으로 연결된 것:

### 7-1. `filesystem`

- **하는 일**: 이 저장소 폴더 안에서 파일·폴더를 읽고 쓰고 목록을 봅니다.
- **범위**: `C:\Users\…\worldmanager` (프로젝트 루트)로 제한되어 있습니다.
- **언제 쓰나**: “이 파일 내용 보여줘”, “이 경로에 저장해줘”처럼 **실제 디스크 작업**이 필요할 때.

### 7-2. `sequential-thinking`

- **하는 일**: 복잡한 일을 **단계별로 생각·검증**하게 돕는 사고 도구입니다.
- **언제 쓰나**: 최적화 라운드, 원인 추적, “한 번에 여러 가설”을 정리할 때.
- **체감**: 답을 바로 찍지 않고, 짧은 생각 단위로 나눠 확인한 뒤 다음 수로 넘어갑니다.

### 7-3. `code-review-graph`

- **하는 일**: 코드베이스를 그래프로 읽어 **어디가 큰지, 무엇이 어디에 연결되는지**를 빠르게 찾습니다.
- **언제 쓰나**: 큰 파일 쪼개기, 수정 영향 범위 보기, `wm_최적화` 중 “어디부터 손댈지” 고를 때.
- **참고**: 그래프 DB 캐시(`.code-review-graph/` 등)는 작업 부산물입니다. 제품 세계관 데이터와는 무관합니다.

### 그밖에 (같은 mcp.json)

- **`memory`**: 프로젝트 안 짧은 기억(엔티티·관계)을 `.cursor/memory.json`에 남겨, 다음 대화에서 맥락을 이어 갑니다.

MCP가 안 보이면 Cursor에서 이 폴더를 연 상태인지, Node.js가 설치돼 있는지, `.cursor/mcp.json`이 그대로인지 확인하세요.

## 8. 에이전트 스킬 — `.agents/skills/`

**제품(World Manager 앱)을 고치거나 다듬을 때** 쓰는 스킬입니다.  
규칙상 여기에 두는 작업용 스킬은 아래만 유지합니다.

- `wm_최적화`
- `ponytail` 계열
- `humanize-korean`

소설 전용 스킬은 **여기가 아니라** `.cursor/skills/`에 둡니다 (9장).

### 8-1. `ponytail` — “가장 게으른(효율적인) 해결”

게으름 = 대충이 아니라 **안 짜도 되는 코드는 안 짜는 것**입니다.

| 모드 | 부르는 법 | 느낌 |
|------|-----------|------|
| lite | `/ponytail lite` | 요청한 것만 만들고, 더 단순한 대안을 한 줄로 알려 줌 |
| full (기본) | `/ponytail` | YAGNI → 표준 라이브러리 → 최소 코드 순으로 강제 |
| ultra | `/ponytail ultra` | 삭제 우선. “그게 정말 필요해요?”부터 물음 |

같이 있는 형제:

| 스킬 | 용도 |
|------|------|
| `ponytail-review` | 과한 설계를 줄 단위로 짚기 |
| `ponytail-audit` | 저장소 전체에서 지워도 될 것 순위 매기기 |
| `ponytail-debt` | `ponytail:` 주석으로 남긴 임시 타협을 장부에 모으기 |
| `ponytail-gain` | “코드·비용·속도” 이득을 숫자로 보기 |
| `ponytail-help` | 위 표 요약 카드 |

끄기: `stop ponytail` / `normal mode`.

### 8-2. `humanize-korean` — AI 티 나는 한국어 다듬기

AI가 쓴 듯한 번역투·과장·기계적 대칭·이모지/불릿 과다 등을 줄이고, **사람이 쓴 듯한 자연스러운 한국어**로 고칩니다.

- 안내 문구, README, 보드에 보이는 짧은 문장에 쓰기 좋습니다.
- 강도: 가볍게 / 보통 / 엄격(heavy) — 요청할 때 말해 주면 됩니다.
- 맞춤법만 고치는 교정기와는 목적이 다릅니다. “사람 말처럼”이 목표입니다.

### 8-3. `wm_최적화` — World Manager 제품 청소·정리

월드매니저 **앱 코드**를 정해진 과정으로 닦는 스킬입니다.

한 사이클에 대략 이런 일을 합니다.

1. 죽은 코드·캐시·테스트 잔해 청소  
2. 큰 파일을 나누고 연결을 맞춤 (`code-review-graph` 활용)  
3. 코드맵·로드 순서 정리  
4. CSS/HTML/JS 정리  
5. 스모크 점검·안내 문구 사람화(`humanize-korean`)

**필수 조합**: `sequential-thinking` + `memory` + `filesystem` + `code-review-graph` + `ponytail` + `humanize-korean`

사용 예:

- `wm_최적화 1회`
- `월드매니저 최적화 3회` (과정 전체를 3번 반복 — 일부만 3번이 아님)
- 끝에 `커밋·푸시`를 붙이면, **그때만** GitHub 반영을 시도합니다. 붙이지 않으면 코드만 다듬습니다.

원칙 요약:

- 삭제 > 추가. 새 폴더·새 라이브러리는 꼭 필요할 때만.
- `data/worlds/<이름>/` 안의 **실제 세계관 데이터는 지우지 않습니다.**
- 테스트용(`wm_demo_` 등)만 치웁니다.

## 9. 소설·세계관 파이프라인 — `.cursor/skills/`

앱을 고치는 스킬(8장)과 달리, 여기는 **소설·세계관 설계·집필**용입니다.  
채팅에서 `/novel-world-orchestrator`, `/worldbuilding-architect`처럼 불러 쓰면 됩니다.

### 9-1. `/worldbuilding-architect` — 레이어로 세계 쌓기

위키처럼 항목만 나열하지 않고, **위층이 아래층의 제약**이 되도록 설계합니다.  
한 번에 한 레이어만. 장르·톤이 없으면 0번부터 질문합니다.

**레이어 순서**

0. 코어 → 1. 코스몰로지 → 2. 지리·생태 → 3. 역사 →  
4. 사회(정치→경제→종교→문화) → 5. 갈등 엔진 →  
6. 인물 인터페이스 → 7. 표면 질감

**절대 원칙 (요약)**

1. 빙산 10% / 배경 90% 분리  
2. 힘으로 풀려면 규칙을 미리 보여 줄 것  
3. 한계·대가가 힘보다 우선  
4. 확장보다 심화  
5. 하나 바꾸면 최소 2개 모듈에 파급  
6. 침묵의 여백 (인물에겐 당연한 것은 설명하지 않음)  
7. 소진 방지 (“혹시 몰라” 설정을 3개 넘게 쌓기 전에 확인)

출력은 보통: 공개용 10% / 배경 90% / 파급 / 열어둘 질문 / **확인 요청 1개**.

> 풀 파이프라인·부모 반환 형식은 서브에이전트  
> `~/.cursor/agents/worldbuilding-architect.md` 를 따릅니다.

### 9-2. `/novel-world-orchestrator` — 여러 스킬을 순서대로 지휘

소설의 매력 설정부터 검수·제출까지, **정해진 순서**로 전문 스킬을 부르고 통과할 때만 다음으로 갑니다.  
세계관 계층이 더 필요하면 단계 2 전후에 `worldbuilding-architect` 레이어를 끼워 넣되, 아래 고정 순서는 건너뛰지 않습니다.

| 단계 | 스킬 | 역할 |
|------|------|------|
| 1 | `fantasy-bestseller-writer` | 핵심 매력, 톤, 독자, 주인공 방향 |
| 2 | `game-world-concept-designer` | 세계관·마법·세력·인과 시스템 |
| 3 | `narrative-structure-analyst` | 서사 구조, 아크, 전환점, 페이싱 |
| 4 | `concept-art-illustrator` | 핵심 이미지·분위기·감각 언어 |
| 5 | `flora-fauna-scholar` | 동식물·생태 설득력 |
| 6 | `geo-astro-scholar` | 지리·지질·천문 설득력 |
| 7 | `medieval-society-historian` | 계급·사회·제도 설득력 |

의견이 갈리면 우선순위는 **스토리 기여도 > 설득력 > 참신함**입니다.  
최종 단계에서는 `fantasy-bestseller-writer`가 **「이것이 제출본이다」**라고 선언합니다.

구성 스킬 파일 위치 예:

```text
.cursor/skills/novel-world-orchestrator/SKILL.md

… (위 표의 나머지 스킬도 동일한 폴더 구조)
```

로컬 Cursor 개인 스킬 폴더(`~/.cursor/skills/`)와 맞춰 두는 것을 권장합니다. 저장소의 `.cursor/skills/`는 GitHub에도 같이 올려 둔 백업·공유본입니다.

## 10. 자주 묻는 말

**127.0.0.1이 PC마다 다르지 않나요?**  
아닙니다. 집 공유기나 인터넷 주소가 아니라, 컴퓨터가 **자기 자신**을 부를 때 쓰는 번호입니다. 어떤 PC에서 앱을 켜도 이 숫자는 같습니다. 다른 폰·다른 PC에서 이 주소로 들어오지는 못합니다.

**인터넷이 필요한가요?**  
앱 자체는 로컬만으로 됩니다. MCP 패키지를 처음 받을 때·GitHub 푸시할 때만 네트워크가 필요합니다.

**폰에서도 되나요?**  
PC 브라우저용입니다. 넓은 화면이 편합니다.

**모듈이 비어 보여요.**  
빈 파일을 열면 기본 16칸을 다시 넣는 처리가 있습니다. 그래도 이상하면 그 세계관 폴더의 `backups/`를 열어 보세요.

**웹사이트로 배포하나요?**  
하지 않습니다. GitHub는 코드 보관용입니다.

**앱 스킬과 소설 스킬을 섞어 두면 안 되나요?**  
역할을 나눕니다.  
- 앱 청소·최적화 → `.agents/skills/` (`wm_최적화`, `ponytail`, `humanize-korean`)  
- 소설·세계관 설계 → `.cursor/skills/` (`novel-world-orchestrator`, `worldbuilding-architect` 등)

**에이전트가 멋대로 커밋해요.**  
요청하지 않으면 커밋·푸시하지 않도록 `AGENTS.md`에 적어 두었습니다. “커밋해줘”, “공식 배포로 푸시해줘”처럼 말할 때만 합니다.
